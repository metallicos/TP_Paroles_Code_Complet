La qualité du modèle dépend directement de la distribution empirique du corpus. Le pipeline de préparation vise donc à réduire le bruit linguistique, contrôler la variance inter-exemples et préserver une représentation exploitable des structures textuelles propres aux paroles.

Colonnes exploitées en priorité: lyrics, playlist_genre, language.

Pipeline de prétraitement et tokenisation

Fonctions implémentées

def preprocess_text(text):
    text = text.lower()
    text = text.replace('\n', ' <NEW_LINE> ')
    text = re.sub(r"[^a-z0-9\s'\-,.:!?()]", '', text)
    text = re.sub(r'\s+', ' ', text).strip()
    return text

def tokenize(text):
    return text.split()

Formulation

x = (w1, ..., wT) ; wt ∈ V ∪ {<UNK>}
x' = [<BOS>, w1, ..., wT, <EOS>]
Encode: e(w) = word2idx[w] sinon e(w)=UNK

Le pipeline reste volontairement déterministe et traçable pour reproduire exactement les expériences.

Slide 7 · Architecture du modèle

Réseau Feed-Forward conditionné par genre

Structure tensorielle

  • Word embedding: [B, 20, 64]
  • Flatten: [B, 1280]
  • Genre embedding: [B, 64]
  • Concat: [B, 1344]
  • Dense1+ReLU+Dropout: [B, 256]
  • Dense2 logits: [B, 12004]

Équations forward

Ew = Wemb[X] ; Eg = G[genre]
h = ReLU([flatten(Ew),Eg]W1 + b1)
z = hW2 + b2
p = softmax(z), pc = exp(zc)/Σjexp(zj)
class LyricsGenerationModel:
    def forward(self, X_batch, genres_batch, training=False, dropout_rate=0.0):
        word_embeds = self.word_embedding[X_batch]
        word_embeds_flat = word_embeds.reshape(batch_size, -1)
        genre_embeds = self.genre_embedding[genres_batch]
        combined = xp.concatenate([word_embeds_flat, genre_embeds], axis=1)
        z1 = xp.dot(combined, self.W1) + self.b1
        a1 = xp.maximum(z1, 0)
        z2 = xp.dot(a1, self.W2) + self.b2
        return z2, a1, combined, relu_mask, dropout_mask
Slide 8 · Fonction objectif

Cross-Entropy, Label Smoothing et Perplexité

Idée simple de la loss

Étape 1: le modèle prédit une probabilité pour chaque mot possible.
Étape 2: on compare cette prédiction avec le vrai prochain mot.
Étape 3: plus l’erreur est faible, meilleure est la prédiction.

La cross-entropy est la mesure d’erreur principale pour ce type de prédiction next-token.

Pourquoi le label smoothing

On évite que le modèle devienne trop sûr de lui trop tôt.
On garde des gradients plus stables pendant l’apprentissage.

Effet attendu: meilleure généralisation sur des exemples non vus.

Perplexité

PPL = exp(L)

Lecture pratique: plus la perplexité baisse, plus le modèle choisit le bon mot avec confiance.

Masquage PAD

valid_mask = (y_batch != PAD_IDX)
d_logits[~valid_mask] = 0.0
d_logits /= max(valid_count, 1)

Les tokens de padding sont ignorés pour ne pas polluer le calcul du gradient.

Slide 9 · Backpropagation

Backpropagation: comment le modèle se corrige

Logique en 4 étapes

1) On calcule l’erreur à la sortie.
2) On propage cette erreur vers les couches précédentes.
3) On mesure l’impact de chaque paramètre sur l’erreur.
4) On met à jour les poids pour réduire l’erreur au passage suivant.
Équation clé: θ ← θ - η ∇θL

Détail important sur les embeddings

grad_word_embedding = xp.zeros_like(self.word_embedding)
token_idx = flat_tokens[valid_mask]
token_grads = flat_grads[valid_mask]

if USING_GPU:
    cupyx.scatter_add(grad_word_embedding, token_idx, token_grads)
else:
    np.add.at(grad_word_embedding, token_idx, token_grads)

Ce mécanisme additionne correctement les gradients quand un même token apparaît plusieurs fois.

Stabilisation numérique

Softmax stable: évite les débordements numériques.
Gradient clipping: empêche des mises à jour trop brutales.

Observations de généralisation

  • Gap train/val favorable (val<train) cohérent avec régularisation dropout.
  • Pas de plateau prématuré critique avant epoch 15.
  • Accuracies train/val montent progressivement (~0.06 → ~0.145).
  • PPL reste élevée en absolu: qualité linguistique encore limitée.

Interprétation mathématique

PPL = exp(L) : toute réduction de L a un effet exponentiel sur la perplexité.
Si L décroît mais que la cohérence reste faible, la limite est architecturale (capacité de dépendances longues).

Slide 12 · Pipeline d’inférence

Décodage probabiliste contrôlé

Équations de sampling

z' = z / T (temperature scaling)
Top-k: zi=-∞ si i ∉ Kk(z)
Top-p: conserver le plus petit ensemble S tel que Σi∈Spi ≥ p
xt+1 ~ Categorical(p')

Pénalités en espace logit

logits_np[tok] -= log(repeat_penalty)
logits_np[tok] -= presence_penalty
logits_np[tok] -= frequency_penalty * count
if repeated_ngram: logits_np[banned] = -1e9

Passer des pénalités en probabilité vers les logits améliore l’effet anti-boucle de manière nettement plus marquée.

Slide 13 · Limites du modèle custom

Pourquoi la qualité génération reste contrainte

Limites structurelles

  • Pas de mémoire séquentielle explicite (contrairement RNN/Transformer).
  • Contexte fixe court (20 tokens) → dépendances longues mal capturées.
  • Sortie multiclasses massive (12k) avec forte entropie.
  • Biais de fréquence vocabulaire → risque de répétition de tokens fréquents.

Conséquences observées

  • Dérive sémantique sur longues générations.
  • Instabilité de structure (couplet/refrain non maintenus).
  • Repetition bigram/trigram élevée sur certains genres.
  • Créativité limitée (mode collapse local sur motifs fréquents).

Lien avec la loi de Zipf

f(r) ≈ C/r : les tokens de faible rang dominent les probabilités cumulées.

Conséquence: sans mécanisme global de contexte, le décodage auto-régressif favorise les motifs fréquents et la répétition locale.

Slide 14 · Transformer et GPT

Fondements mathématiques de la branche GPT

Self-attention (décodeur)

Q = XWQ, K = XWK, V = XWV
Attention(Q,K,V) = softmax((QKᵀ / √dk) + M) V
M = masque causal (empêche l’accès aux tokens futurs)
MultiHead(X)=Concat(head1,...,headh)WO

Fine-tuning objectif CLM

L = -Σt log P(xt | x<t)

Le modèle GPT-2 est déjà pré-entraîné; le fine-tuning réalise une adaptation de domaine (lyrics) à faible learning rate.

learning_rate=5e-5
warmup_steps=50
weight_decay=0.01
fp16=True si CUDA

Intuition théorique du fine-tuning

θnew = θpretrain - η∇Ldomain(θ)

Le fine-tuning ajuste localement un espace latent déjà riche: meilleure cohérence globale avec peu d’époques.

Slide 16 · Comparaison modèles

Comparaison entre notre modèle et GPT-2

Lecture synthétique

  • model custom: excellent pour expliquer les mécanismes d’apprentissage.
  • GPT-2: meilleure cohérence textuelle et meilleure stabilité sur longues séquences.
  • Coût: le model custom est plus léger, GPT-2 est plus exigeant en calcul.
  • Positionnement final: approche hybride = explicabilité + qualité de génération.

Conclusion de comparaison

Le graphe confirme le compromis attendu: le modèle custom reste idéal pour l’analyse pédagogique et la traçabilité, tandis que GPT-2 améliore la qualité linguistique globale. Le choix dépend donc de l’objectif: compréhension interne du modèle, ou qualité finale de génération.
